# タクティクスの仕組みと利点

タクティクスは、ゴールと仮定から、必要な証明項を構成する仕組みである。Lean では、`by` の後にタクティクスを並べて証明を書くことができる。

例えば `example : P ∧ Q := by ...` では、証明すべき命題 `P ∧ Q` が最初のゴールになる。タクティクスは、このゴールを小さな課題に分けたり、使える定理を探したりして証明項を組み立てる。内部では、Lean の式の内部表現を木構造のデータとして扱ういわゆるメタプログラミングが使われる。

証明を完成させるために、タクティクスは原理的には必須ではない。タクティクスを使って書かれた証明は、同じ仮定や公理のもとで、タクティクスを使わない証明項としても表現できる。タクティクスの利点は、証明項の組み立てに必要な労力を減らせることにある。

## 1. 証明項の直接記述とゴールからの構成

命題 `P ∧ Q` の証明は、`P` の証明と `Q` の証明を `And.intro` に渡して構成できる。同じ証明をタクティクスで書くと、まずゴールの形に応じて証明を分け、それぞれに必要な項を渡す。

```lean
example (P Q : Prop) (hp : P) (hq : Q) : P ∧ Q :=
  And.intro hp hq

example (P Q : Prop) (hp : P) (hq : Q) : P ∧ Q := by
  constructor
  · exact hp
  · exact hq
```

直接書く場合は、書き手が `And.intro` を選ぶ。タクティクスの `constructor` は、ゴールの型が `And P Q` であることを調べ、コンストラクターを適用するために必要な引数を新しいゴールにする。

```text
P Q : Prop
hp : P
hq : Q
⊢ P ∧ Q
```

`constructor` の後には、同じ仮定を使える二つのゴールができる。

```text
⊢ P

⊢ Q
```

`exact hp` と `exact hq` がそれぞれの項を渡すと、全体の証明が完成する。タクティクスは、結論から逆向きに「何を用意すれば証明が完成するか」を決める手段になる。

## 2. ゴールとメタ変数

ゴールは、型と局所的な変数・仮定を伴う、未完成の項である。内部では、未確定の項を表すメタ変数として管理される。タクティクスはメタ変数に項を割り当て、必要なら新しいメタ変数を作って証明を進める。

上の論理積の例は、説明用の記法では次のように表せる。`?goal`、`?left`、`?right` は未完成の項の名前である。

```text
?goal : P ∧ Q

?goal := And.intro ?left ?right
?left : P
?right : Q

?left := hp
?right := hq
```

最終的に `?goal` に対応する項は `And.intro hp hq` になる。`exact` は現在のゴールを項で埋め、`apply` は定理を適用するために必要な前提を新しいゴールにする。`intro` は含意や全称命題の引数を導入し、引数を受け取った後の項を作る課題へ進む。

ゴールは関数の返り値に限られない。式の途中にある `by` にも、周囲から期待される型がある。

```lean
example (P Q : Prop) (hp : P) (hq : Q) : P ∧ Q :=
  And.intro hp (by exact hq)
```

内側の `by` に期待される型は `Q` であり、内側のタクティクスは `Q` をゴールとして実行される。タクティクスによって命題以外の値を構成することもできる。`by` の記法は、[`by`：タクティクスによる項の作成](../syntax/by.md)を参照。

## 3. メタプログラミングによる型と式の検査

メタプログラミングは、プログラムの式や型をデータとして扱い、別のプログラムや証明を構成する方法である。Lean のタクティクス実装では、式を `Lean.Expr` というデータとして扱い、ゴールの型、仮定、定理の宣言などを調べられる。

例えば `constructor` はゴールの型から帰納型とそのコンストラクターを調べる。`simp` は式の構造を調べ、登録された等式や同値を使って簡単化する。タクティクスは、目的の命題の証明がすでにあることを前提にせず、目的の命題を表す式から証明の構成を始められる。

通常の証明項でも、命題、仮定の証明、既存の定理を引数として使える。例えば `hpq : P → Q` は、`P` の証明を受け取って `Q` の証明を返す関数である。ただし `P : Prop` を引数に取ること自体は、`P` の式の構造を検査する機能を与えない。任意の `P` に対して「論理積なら分解する」と処理するには、命題を表す式をデータとして扱う仕組みが必要になる。

タクティクスの実装も Lean で書ける。タクティクスは、構文を解釈して暗黙引数などを補い、内部の項を構成する elaboration の段階で実行される。実行環境 `Lean.Elab.Tactic.TacticM` は、項の elaboration の機能に加えて、現在のゴールの一覧などを管理する。次の例では、[`run_tac`](../tactics/run_tac.md) でメタプログラミング用のコードを実行し、現在のゴールの型を表示する。

```lean
import Lean

example : True := by
  run_tac do
    let target ← Lean.Elab.Tactic.getMainTarget
    Lean.logInfo m!"Target: {target}"
  exact True.intro
```

`getMainTarget` が返すのは、ゴールの型 `True` を表す `Lean.Expr` であり、`True` の証明ではない。表示だけではゴールは解決されず、後続の `exact True.intro` が証明項を渡す。

タクティクスの構文は、既存のタクティクスへ展開するマクロや、`TacticM` の処理を実行する elaborator で実装できる。また、タクティクスを使わない式でも、暗黙引数の推論などの elaboration は期待される型を利用する。期待される型の利用そのものがタクティクスだけの機能というわけではない。

## 4. ゴールの書き換えと元の命題の証明

`rw` などは、証明途中に表示されるゴールの型を別の形へ変える。例えば `a = b` を使って `a + 1 = b + 1` の左辺を書き換えると、残る課題は `b + 1 = b + 1` になる。

```lean
example (a b : Nat) (hab : a = b) : a + 1 = b + 1 := by
  rw [hab]
```

`rw` は書き換え後の反射的な等式も閉じるので、この例では追加のタクティクスが不要である。元の等式の証明は、項で直接書けば `congrArg (fun n => n + 1) hab` でも構成できる。

ゴールの変化は、元の定理の主張を自由に変更する操作ではない。タクティクスは、書き換え後の課題の解決から元の型の項を構成できるように、等式の証明などを使って両者を結び付ける。最終的に必要なのは、最初に宣言した命題の型を持つ証明項である。

## 5. タクティクスの利点と証明の検査

タクティクスを使うと、未解決の課題と使える仮定を見ながら、大きな証明を段階的に組み立てられる。`apply` は結論から必要な前提へ進み、`simp` は式の整理を、`exact?` は使える証明の探索を行う。定理の適用や書き換えの細部を毎回手で組み立てる負担も減らせる。

一方、`hp` や `And.intro hp hq` のように短い項で済む場合は、直接書く方法も読みやすい。項の直接記述とタクティクスは、一つの証明の中で組み合わせられる。

タクティクスによって構成された証明項は、Lean のカーネルによる型検査を受ける。完成した項が宣言された型を持つ必要である。

タクティクスが構成した項は [`show_term`](../tactics/show_term.md) で、名前付きの定理の証明は [`#print`](../commands/print.md) で確認できる。
