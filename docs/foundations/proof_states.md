# ゴールと証明状態

ゴールとは、Lean で証明や値を作る途中に残っている「指定された型の項を作る」という課題である。命題 `P` の証明を書く場合は、`P` 型の証明項を作ることがゴールになる。各ゴールには、必要な項の型と、その項を作るために使える変数や仮定がある。

証明状態とは、タクティクスで処理する未解決のゴールを順に並べたものである。証明を進めると、ゴールが解決されたり、別のゴールに変わったり、複数の小さな課題に分かれたりする。

## ゴールの意味

次の例では、`by` の右側で `P` 型の項を作る必要があるため、最初のゴールは `P` である。

```lean
example (P : Prop) (hp : P) : P := by
  exact hp
```

`hp : P` は、すでに使える `P` の証明である。`exact hp` が必要な証明項を渡すと、ゴールが解決される。

記事やタクティクスの説明で「ゴールが `P`」と言うときは、通常、作るべき項の型が `P` であることを指す。ゴール全体には、使える変数や仮定も含まれる。同じ `P` を証明する課題でも、`hp : P` が使える場合と、使える証明がない場合とでは、証明の進め方が異なる。

命題以外の型もゴールになる。たとえば `def three : Nat := by ...` では、`Nat` 型の値を作ることが課題である。具体例は [`by` の「式の中での使用と値の作成」](../syntax/by.md#式の中での使用と値の作成)を参照。

## 証明状態の表示場所

VS Code の Lean 4 拡張機能では、証明状態はエディタの横に開く「Lean Infoview」パネルに表示される。`by` の証明内にカーソルを置くと、その位置で使える変数や仮定と、未解決のゴールを確認できる。上の例では、`by` の直後にカーソルを置くと、次の証明状態が表示される。

```text
P  : Prop
hp : P
⊢ P
```

カーソルをタクティクスの実行前後に移すと、ゴールや仮定の変化を確認できる。すべてのゴールが解決されると、Infoview にはゴールが残っていないことが表示される。

## `⊢` と証明状態の読み方

`⊢` は「ターンスタイル」と呼ばれる。Lean の証明状態では、使える変数・仮定と、作るべき項の型を区切る記号である。`⊢ P` は「現在の仮定を使って、`P` の証明を作る必要がある」と読む。

上の状態表示の例では、`⊢` より上の行が使える変数や仮定、`⊢` の右側の `P` が現在のゴールの型である。`P : Prop` は「`P` は命題」、`hp : P` は「`P` の証明を `hp` という名前で使える」という意味である。この場合は `exact hp` で証明を渡すと、そのゴールが解決される。

## タクティクスによるゴールの変化

含意の証明では、`intro` で前提を仮定に加え、結論を証明する課題へ進める。論理積の証明では、`constructor` で左右それぞれの証明を課題にできる。

```lean
example (P : Prop) : P → P ∧ P := by
  intro hp
  constructor
  · exact hp
  · exact hp
```

`by` の直後には、含意全体がゴールになっている。

```text
P : Prop
⊢ P → P ∧ P
```

`intro hp` の後には、仮定 `hp : P` が加わり、ゴールの型が結論 `P ∧ P` に変わる。

```text
P : Prop
hp : P
⊢ P ∧ P
```

`constructor` の後には、左右それぞれの `P` を証明する二つのゴールができる。

```text
case left
P : Prop
hp : P
⊢ P

case right
P : Prop
hp : P
⊢ P
```

`case left` と `case right` は、ゴールに付いた名前を示す。証明状態の先頭にあるゴールを「主ゴール」と呼び、多くのタクティクスは主ゴールに作用する。`·` のブロックでは一つのゴールに集中して証明を書く。上の例では、二つのブロックの `exact hp` がそれぞれのゴールを解決し、元の含意の証明が完成する。

ゴールの変化は、元の定理の主張を変更する操作ではない。新しいゴールの解決から、元の型の項を組み立てられるように証明が進む。内部の仕組みは[タクティクスの仕組みと利点](tactics.md)を参照。

## 論理学のターンスタイルとの違い

論理学では、通常 $\Gamma \vdash P$ は「仮定の集まり $\Gamma$ から、推論規則を使って $P$ を導出できる」という意味である。左側の仮定を省いた $\vdash P$ は、仮定なしで $P$ を証明できることを表す。

Lean の証明状態では、この形をこれから解決する証明の課題として表示する。表示されたこと自体は、`P` が証明済みであることも、現在の仮定から証明できることも保証しない。

たとえば、証明途中で次の表示が出ても、`False` が証明されたことにはならない。

```text
⊢ False
```

これは「`False` を証明する必要がある」という未解決のゴールである。証明を進める途中には、このように解決できないゴールを作ってしまうこともある。

コード中で `rw [hab] at h ⊢` のように書く場合は、`⊢` が操作対象として現在のゴールを指定する。この用法は [`rw` の対象指定](../tactics/rw.md)を参照。`⊢` 単独はタクティクスの命令ではない。
