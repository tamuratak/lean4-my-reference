# カリー・ハワード対応と Lean の命題・証明

カリー・ハワード対応（Curry–Howard correspondence）は、命題を型として、その証明をその型の項として表す考え方である。Lean で命題 `P` を証明することは、型 `P` を持つ項を構成することに当たる。含意の証明には関数、論理積の証明には両方の証明をまとめるコンストラクターを使うなど、論理の推論が項の構成と対応する。

## 1. 命題・証明・`Prop` の関係

`P : Prop` は「`P` が命題である」、`h : P` は「`h` が `P` の証明である」という意味である。命題を型として持つ項を、証明項（proof term）と呼ぶ。コロンの左側が項、右側がその項の型という関係は、データでも証明でも共通している。

| Lean の表現 | 項 | 項の型 | 意味 |
| --- | --- | --- | --- |
| `3 : Nat` | `3` | `Nat` | 自然数の値 |
| `Nat : Type` | `Nat` | `Type` | データ型 |
| `P : Prop` | `P` | `Prop` | 命題 |
| `h : P` | `h` | `P` | 命題 `P` の証明 |

例えば `2 + 3 = 5` という式の型は `Prop` であり、その式を型として持つ項が等式の証明になる。

```lean
#check (2 + 3 = 5 : Prop)
#check (rfl : 2 + 3 = 5)

theorem two_add_three : 2 + 3 = 5 := rfl
```

`:= rfl` の `rfl` は、等式の反射性を表す証明項である。`2 + 3` は計算すると `5` になるため、反射性によって証明できる。`two_add_three` という名前で登録される項の型は `2 + 3 = 5` である。用意されている基本的な証明の一覧と、証明項・タクティクスとしての `rfl` の違いは、[証明項と基本的な証明の一覧](proof_terms.md)を参照。

### 命題の形成と真偽の判定

`P : Prop` という型の確認は、`P` が命題として書けていることを意味する。偽の命題 `False` も `Prop` に属するので、命題として受理されることだけでは証明は得られない。証明には、別途 `h : P` に当たる項が必要になる。

また、`Bool` の値 `true` は真偽値のデータである。命題 `P` の証明として使うには、型が `P` である項を渡す必要がある。`decide` や `by decide` と命題の関係は、[`decide`](../tactics/decide.md)で説明している。

## 2. 含意の証明と関数

含意 $P \to Q$ の証明は、`P` の証明を受け取り、`Q` の証明を返す関数である。Lean の `P → Q` は、その関数の型を直接表している。

```lean
example (P : Prop) : P → P :=
  fun hp => hp

example (P Q : Prop) (hpq : P → Q) (hp : P) : Q :=
  hpq hp
```

`fun hp => hp` は、仮定として受け取った `P` の証明をそのまま返す。`P → P` を証明するために、先に `P` 単独の証明を用意する必要はない。`P` の証明を渡された場合に、結論の証明を返せればよい。

二つ目の例の `hpq hp` は、関数適用によって `Q` の証明を得る操作であり、論理の「$P$ と $P \to Q$ から $Q$ を導く」という推論に対応する。

否定 `¬ P` は `P → False` と定義されている。否定の証明も、仮定した `P` の証明から矛盾の証明を返す関数になる。

## 3. 論理結合子と証明の構成・分解

論理積や論理和は、証明を構成するためのコンストラクターを持つ命題である。証明を作る操作はコンストラクターの適用、作った証明を利用する操作は成分の取り出しや場合分けに対応する。

| 命題 | 証明の構成 | 証明の利用 |
| --- | --- | --- |
| `P ∧ Q` | `And.intro hp hq` で両方の証明をまとめる | `h.left`・`h.right` でそれぞれの証明を取り出す |
| `P ∨ Q` | `Or.inl hp` または `Or.inr hq` で側と証明を指定する | 左右の場合それぞれで、同じ結論の証明を作る |
| `P ↔ Q` | `Iff.intro hpq hqp` で両方向の含意をまとめる | `h.mp`・`h.mpr` で各方向の含意を使う |

例えば、`P` の証明と、`P` から `Q` を導く関数を受け取ると、両方の証明をまとめて `P ∧ Q` の証明を作れる。

```lean
example (P Q : Prop) (hp : P) (hpq : P → Q) : P ∧ Q :=
  And.intro hp (hpq hp)

example (P Q : Prop) : (P ∧ Q) → P :=
  fun h => h.left
```

二つ目の例は、論理積の証明を受け取り、左側の命題の証明を返す関数である。コンストラクターの省略記法 `⟨…⟩` や各記号の書き方は、[論理の記号](../syntax/logical_symbols.md)を参照。

## 4. 全称命題・存在命題と依存型

全称命題 $\forall x : \alpha,\ R(x)$ の証明は、任意の値 `x : α` を受け取り、`R x` の証明を返す関数である。結果の型 `R x` が引数 `x` に依存するため、依存関数型を使う。

```lean
example : ∀ n : Nat, n + 0 = n :=
  fun n => Nat.add_zero n
```

`fun n => Nat.add_zero n` の引数は自然数のデータで、戻り値はその自然数についての等式の証明である。含意では証明を引数として受け取り、全称命題では量化した対象を受け取る。どちらも Lean の関数で表現できる。

存在命題 $\exists x : \alpha,\ R(x)$ の証明は、証人となる値 `x` と、値に対応する型 `R x` の証明を渡して構成する。

```lean
example : ∃ n : Nat, n + 1 = 4 :=
  Exists.intro 3 (rfl : 3 + 1 = 4)
```

証人は `3`、条件の証明は型 `3 + 1 = 4` を持つ `rfl` である。存在命題の証明を仮定として使う際には、証人 `n` と証明 `hn : n + 1 = 4` を取り出して、別の命題の証明を組み立てられる。

### 存在命題とデータの組の違い

存在命題 `∃ x : α, R x` は `Prop` に属する。証人と条件の証明をまとめる点は部分型 `{x : α // R x}` と似ているが、存在命題の証明から証人を一般に計算可能なデータとして取り出すことには制限がある。条件を満たすデータ自体を保持して計算に使う場合は、[部分型](../syntax/subtype.md)を利用できる。証明の除去の制限や選択公理は、[型システムの基礎](type_system.md#5-証明の無関連性)を参照。

## 5. タクティクスのゴールと証明の項

タクティクスは、目的の型を持つ項を段階的に構成する機能である。ゴール `⊢ R` は「型 `R` の項をここで作る必要がある」という要求を表し、仮定 `hp : P` は、その構成に使える項を表す。

含意をつなぐ証明は、項を直接書く方法と、タクティクスで組み立てる方法の両方で表せる。

```lean
theorem chainTerm (P Q R : Prop) (hpq : P → Q) (hqr : Q → R) : P → R :=
  fun hp => hqr (hpq hp)

theorem chainTactic (P Q R : Prop) (hpq : P → Q) (hqr : Q → R) : P → R := by
  intro hp
  apply hqr
  exact hpq hp
```

`intro hp` は、`P → R` という関数の引数を導入する。ゴールの中心部分は次のように変わる。

```text
hpq : P → Q
hqr : Q → R
⊢ P → R
```

`intro hp` の後は、受け取った `P` の証明を使って `R` の証明を作る。

```text
hpq : P → Q
hqr : Q → R
hp : P
⊢ R
```

`apply hqr` は、`hqr` に渡す引数の証明を新しいゴールにする。

```text
hpq : P → Q
hqr : Q → R
hp : P
⊢ Q
```

`exact hpq hp` が型 `Q` の項を渡すと、`hqr (hpq hp)` により型 `R` の項が完成する。全体として、直接書いた `fun hp => hqr (hpq hp)` に対応する証明を組み立てている。

## 6. カーネルの型検査と証明の前提

Lean のカーネルは、構成された項が宣言された命題の型を持つかを検査する。例えば `hpq : P → Q` の適用には型 `P` の引数が必要であり、型 `Q` の項を得た後は、型 `Q` の証明が要求される場所で使える。タクティクスで書いた場合も、検査対象は完成した証明の項である。

型検査が保証するのは、定義・仮定・利用した公理のもとで、その命題の証明が成立することである。仮定付きの定理は、仮定の証明を受け取って結論の証明を返す関数であり、仮定自体の成立まで無条件に示すものではない。意図した数学の概念を表せているかは、命題や定義の内容も確認する必要がある。

Lean では、同じ命題の証明どうしを定義上等しいものとして扱い、コンパイル時には証明を消去する。証明の項は正しさを検査するために使われ、その内容を実行時データとして区別する扱いには制限がある。詳しくは[証明の無関連性](type_system.md#5-証明の無関連性)を参照。
