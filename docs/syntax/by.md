# `by`：タクティクスによる項の作成

`by` は、**タクティクスで作った証明や値を、一つの項として使う**構文である。

```lean
example (P : Prop) (hp : P) : P := by
  exact hp
```

`:=` の右側に必要なのは `P` 型の項である。`by` に入ると、Lean はそれをゴールとして表示する。

```text
P  : Prop
hp : P
⊢ P
```

`exact hp` がゴールの証明を渡し、`by` 全体が `P` の証明になる。ここで `by` は式を始める文法、`exact` は内側で使うタクティクスである。

## `⊢` と証明状態の読み方

`⊢` は「ターンスタイル」と呼ばれる。論理学では、通常 `Γ ⊢ P` は「仮定の集まり `Γ` から、推論規則を使って `P` を導出できる」という意味である。左側の仮定を省いた `⊢ P` は、仮定なしで `P` を証明できることを表す。

Lean の証明状態では、この形を**これから解決する証明の課題**として表示する。`⊢ P` は「現在の仮定を使って、`P` の証明を作る必要がある」と読む。表示されたこと自体は、`P` が証明済みであることも、現在の仮定から証明できることも保証しない。

上の状態表示では、`⊢` より上の行が使える変数や仮定、右側の `P` が現在のゴールである。`P : Prop` は「`P` は命題」、`hp : P` は「`P` の証明を `hp` という名前で使える」という意味である。この場合は `exact hp` で証明を渡すと、そのゴールが解決される。

たとえば、証明途中で次の表示が出ても、`False` が証明されたことにはならない。

```text
⊢ False
```

これは「`False` を証明する必要がある」という未解決のゴールである。証明を進める途中には、このように解決できないゴールを作ってしまうこともある。この `⊢` は状態表示の区切りである。

コード中で `rw [hab] at h ⊢` のように書く場合は、`⊢` が操作対象として現在のゴールを指定する。この用法は [`rw` の対象指定](../tactics/rw.md)を参照。`⊢` 単独はタクティクスの命令ではない。

## 式の中での使用と値の作成

普通の式の中にも置ける。

```lean
example (P Q : Prop) (hp : P) (hq : Q) : P ∧ Q :=
  ⟨hp, by exact hq⟩
```

この `by` に期待される型は `Q` なので、内側のゴールも `Q` になる。

命題以外の値を作ることもできる。

```lean
def three : Nat := by
  exact 3

example : three = 3 := rfl
```

複数行のタクティクスは、`by` より深く字下げし、同じ段階の命令を揃える。未解決のゴールが残ったままでは完成した項にならない。

命令の使い方は[タクティクス一覧](../tactics/README.md)を参照。
